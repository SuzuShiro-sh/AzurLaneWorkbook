# 工作簿与数据说明

AzurLaneWorkbook 将游戏数据快照与换装计划统一整合在 Excel 工作簿中。

命令参数见 [CLI 说明](CLI.md#工作簿流程)，MCP 协议参数见 [MCP 说明](MCP.md#工作簿操作流程)。

## 核心文件与快照机制

| 文件路径 | 用途 | 生效时机 |
| --- | --- | --- |
| 仓库根目录 `workbook-layout.xlsx` | 随源码维护的默认模板 | 开发构建时使用 |
| 程序旁 `.suzushiro/workbook-layout.xlsx` | 当前安装使用的实际模板 | 生成新工作簿时生效 |
| `.suzushiro/data/workbooks/fleet-001.xlsx` | 包含数据快照与配装输入的工作簿 | 检查与执行时读取 |

- **快照特性**：工作簿中记录的是生成时的数据静态快照。通过 CLI 或 MCP 进行的外部直接操作不会实时刷新已有表格；执行换装前，工具会根据当前游戏数据重新进行前置核验。
- **模板与版本兼容**：修改 `.suzushiro/workbook-layout.xlsx` 模板后，已有工作簿的列结构保持不变。模板摘要或字段校验不匹配时，旧工作簿不能继续检查与执行，需重新生成后再整理填写换装计划。
- **自动备份**：正式执行换装操作前，程序会自动在 `.suzushiro/data/backups/` 中创建源文件的快照备份。

## 表格结构与填报规则

默认生成 8 张工作表（含 180 列），最核心的两张为“**配装计划**”（50 列）与“**装备总表**”（33 列）。

### 单元格视觉标记

| 样式 | 含义 | 说明 |
| --- | --- | --- |
| 浅绿单元格 | 计划输入区 | 换装与装备操作的填写区域（支持下拉选项） |
| 浅灰锁定单元格 | 只读数据区 | 展示当前持有状态、装备属性与基础数值 |
| 淡蓝锁定行 | 未持有舰船 / 装备 | 仅作图鉴参考与科技查询，不可编辑 |

请勿修改工作簿中的隐藏字典、对象主键 ID 或表头结构，否则可能导致工具解析校验失败。

### 配装计划表（按舰船规划 5 个槽位）

- **持有舰船行**：每艘已拥有舰船独占一行，展示等级、属性面板、技能及 1–5 号槽位的“当前装备”与“更换／处理”目标。
- **未持有舰船行（淡蓝）**：展示基础配置与科技属性，数据区锁定。
- **舰船名称显示**：若舰船已誓约且修改过备注名，显示格式为 `备注名(真实名)`；获取方式查询与 Wiki 链接统一按真实名处理。

### 装备总表（按来源查看库存）

- **聚合展示**：仓库中同配置、同强化等级的装备按数量汇总为一行；舰船槽位装备逐件单独展示。
- **操作支持**：提供“操作”、“处理数量”、“目标强化等级”三列，支持针对指定库存批量规划强化或拆解。

## 换装计划完整流程

### 1. 填写换装目标

在“配装计划”表中对应舰船的“**槽位N更换／处理**”列下拉选择：

| 选项类型 | 含义 | 示例 |
| --- | --- | --- |
| 留空 | 保持当前槽位现状 | - |
| 卸下 | 将当前装备卸至仓库 | `卸下` |
| 拆解 | 将当前装备卸下并拆解 | `拆解` |
| 仓库来源 | 从仓库中选择已有装备装配 | `仓库×8｜装备名称 T3` |
| 图纸合成 | 消耗图纸与物资自动合成后装配 | `合成×32｜装备名称 T3` |
| 舰船调拨 | 从其他舰船槽位调配装备 | `贾维斯·槽2｜装备名称 T3` |

- **来源配额**：计划器会自动核算共享的图纸、物资与库存，超额或冲突的分配会被检查拦截。
- **扩展策略列（可选启用）**：仅选择装备族、未指定来源时，可填写“来源策略”（如 `仅仓库`、`仓库→合成`）；带来源的目标选项已确定来源，此列须留空。“分配优先级”可按需启用。

### 2. 规划批量强化与拆解

在“装备总表”中对目标行填写：
- **强化**：填写“处理数量”与“目标强化等级”（等级不得超过上限，且需满足材料与物资要求）。
- **拆解**：填写“处理数量”，强化等级留空（数量不得超过库存，拆解不可逆）。

### 3. 检查计划（Dry-Run）

保存 Excel 文件后，在终端运行预检：

```powershell
# 仅核验计划可行性并输出消耗详情（不修改游戏装备，不改写工作簿）
.\AzurLaneWorkbook.exe --instance mumu12:0 check fleet-001.xlsx

# 核验计划并将检查状态与错误写回工作簿
.\AzurLaneWorkbook.exe --instance mumu12:0 check-save fleet-001.xlsx
```

检查过程会自动排查材料是否充足、来源是否存在冲突，并规划出合理的依赖执行顺序（如优先合成、强化再装备）。

### 4. 正式执行换装

确认预检结果与资源消耗后，执行换装：

```powershell
.\AzurLaneWorkbook.exe --instance mumu12:0 execute fleet-001.xlsx
```

执行流程：
1. 预检计划并核对当前游戏状态与资源。
2. 自动备份源工作簿至 `data/backups/`。
3. 按依赖顺序向游戏发送换装、强化或拆解指令。
4. 重新从游戏读取最新状态，并将结果写回工作簿（配装输入保留，装备总表操作输入清空）。

## 模板布局维护

布局模板控制工作簿中各表的可见性与字段展示方式：

```powershell
# 验证当前模板结构与字段有效性
.\AzurLaneWorkbook.exe layout-check

# 生成纯样式预览文件（不含游戏数据）
.\AzurLaneWorkbook.exe layout-preview

# 检查当前契约并在模板缺失新字段时生成升级文件
.\AzurLaneWorkbook.exe layout-upgrade
```

- 字段模式分为 `显示`、`隐藏`（生成但在 Excel 中默认隐藏）与 `不生成`（不包含该列）。
- 基础配装所必需的核心字段不受显示开关影响，底层逻辑会自动确保换装依赖数据的完整读取。

## 阵营科技信息

配装计划表中提供科技相关信息（数据直接来源于游戏客户端统计）：

| 列名 | 说明 |
| --- | --- |
| 科技加成 | 汇总获得及 120 级奖励的受益舰种与属性（多项时以分号分隔，支持 Excel 包含筛选；达成状态见阶段科技列） |
| 获得科技 | 拥有该舰船时提供的科技点数与属性加成达成状态 |
| 满星科技 | 满星突破时提供的科技点数达成状态 |
| 120级科技 | 达到 120 级时提供的科技点数与属性达成状态 |

科技达成状态以舰船组历史为准，单艘舰船退役不影响已解锁的阵营科技。

## 舰船获取途径与网络缓存

若在偏好设置中启用了“获取方式”列，工作簿会按更新策略读取本地缓存或 BWiki 资料，展示该舰船的建造池、关卡掉落与活动获取信息。

### 缓存更新策略

| 策略 / 命令 | 行为 |
| --- | --- |
| `use_cache`（默认） | 仅读取本地已有缓存，不产生网络请求；无缓存项提示“资料未缓存” |
| `refresh` | 生成新工作簿时尝试联网刷新所需资料，失败时保留旧缓存 |
| `update-acquisition --mode missing` | 补充抓取工作簿中缺失或先前失败的舰船资料（推荐） |
| `update-acquisition --mode refresh` | 强制重新拉取所涉及的全部舰船资料 |

```powershell
# 在线增量补全资料缓存
.\AzurLaneWorkbook.exe update-acquisition fleet-001.xlsx --mode missing
```

- 缓存文件保存在 `.suzushiro/data/cache/ship-acquisition/`。
- 请求过程访问限流、重试退避与安全冷却机制，可在进度中随时发起取消。
